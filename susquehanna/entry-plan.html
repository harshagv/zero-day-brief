01 — Day-one thesis

What I'd actually do first

Before touching a single control, I'd build the map that doesn't exist yet in most security teams this size: every path a credential or session can take from a workstation to a production trading system, with the control that gates each hop named and owned. That map is what turns "harden endpoints, implement PAM, manage cloud posture" from three separate initiatives into one prioritised list — and it's the same artifact I'd use to onboard myself, because I can't harden or triage what I haven't traced first.

↳ re: "Engineer and implement authentication and privileged access controls, harden endpoints and applications, implement threat prevention controls, and design and manage Susquehanna's cloud security posture"

03 — Entry plan

First 90 days

01

Days 1–30

Trace before touching anything
  • Build the credential-to-production access-path map: identity provider → endpoint → network/proxy → PAM → cloud control plane, naming the control at each hop.
  • Shadow the firewall/proxy triage rotation as an observer — this is the domain with no verified evidence, so it gets the earliest and most deliberate exposure, not the latest.
  • Get read access to existing IAM/RBAC policies and endpoint hardening baselines; run my IAM privilege auditor (below) against what's exportable to build a real, current baseline rather than assume one.
02

Days 31–60

Ship one real fix, not a plan for one
  • Close the highest-severity finding the auditor surfaces — a wildcard grant or an unconditioned sensitive action — end to end: identify, scope down, test, deploy.
  • Pair with the network/firewall on-call rotation on two live tickets, specifically to build the TCP/IP-and-routing-level fluency the JD requires and I currently can't evidence.
  • Extend the auditor or an equivalent tool to cover one more control surface based on what the 30-day map actually found gaps in — not what looks good to build.
03

Days 61–90

Own a control domain independently
  • Take standing ownership of one control area from the 30-day map — most likely PAM tooling or cloud posture automation, where I have verified depth — including its triage rotation participation.
  • Present the access-path map and the closed findings to the wider security team as a reusable artifact for onboarding future hires.
  • Have a documented, honest answer to "where are you still ramping" for endpoint hardening and networking, with a concrete plan attached — not a vague acknowledgment.
